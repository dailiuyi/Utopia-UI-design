# 可直接复制给开发 Agent 的提示词

下面代码块可单独使用；如果能附文件，优先同时交付 `skills/utopia-mr-ui/` 整个目录，获得完整变量、状态和 Unity 约束。最后一段是本次具体任务，使用时换成实际页面/组件即可。

```text
你负责一个 Unity 6 手机 MR 决斗游戏的 UI 设计与实现。请先遵循当前任务范围：我只要求设计时不要修改工程，我要求实现时才编写和接入代码。若能读取随附 skills/utopia-mr-ui/SKILL.md，请先读该文件，按其中链接读取相关规范与设计变量；无法使用 Skill 的 Agent 则按以下约定工作。

已确认：
1. 只做 Android 和 iOS 手机，中文主界面；不做头显、手柄或其他硬件。
2. Unity 6，具体 6000.x、uGUI/UI Toolkit、渲染管线、输入系统与定位 SDK 从现有工程读取并沿用，不擅自迁移。没有工程时标注技术选型待确认，不声称已接入 Unity。
3. 竖屏用于准备与重定位，横屏用于战斗。旋转只更新布局和交互就绪状态，不重建决斗场、角色或对局。
4. 相机通过重定位算法对齐已登记的现实场景，在场景中的虚拟决斗场进行类似《拳皇》的战斗呈现。不要替换成随意点平面放置，也不要据此推定连招、摇杆或攻击键方案。
5. 玩家操作方式未定。共享 HUD 与操作模块分离；直接操控、指令、观战只作为可替换候选，不把候选做成已确认需求。不必为此停止共享 HUD 的设计。

视觉目标：参考我提供的进化酒馆攻壳主题海报。近黑底、明黄与奶白，强烈中文宋体/明朝体标题，清晰黑体正文，细切角边框、角括号、少量黑黄斜纹、淡机械线稿。核心是黑黄工业气质，不能只因为“攻壳”就生成青蓝 HUD、绿字终端、紫色渐变或满屏玻璃卡片。

建议起始值（可随真机验证调整，不是海报精确取色）：底色 #090A08、面板 #17180F、强调 #E6D300、黄底文字 #101108、主文字 #F5F1D6、次文字 #C6C4AE；8 单位间距节奏，2 单位主边线，8–16 单位切角；按下反馈约 120ms，面板过渡约 200ms。这些是参考画布单位，不是手机物理像素。使用同一主题来源，不到处散落独立常量。

准备页可以使用强衬线标题和机械底纹，战斗页减少装饰；顶部清楚显示双方生命值及回合状态，中央优先显示现实决斗场和角色，下方两侧给操作模块留空间。中文按钮与关键提示完整可读，重要文字有可靠深色底板，不能靠相机背景衬托。海报中的比赛名称、标志、角色与文案不自动成为游戏资产。没有正式游戏名和角色名时，明确标注示例。

状态必须由真实业务驱动：相机授权、设备能力、设备追踪、场景重定位、决斗场绑定、朝向和比赛状态分别处理。追踪正常不等于重定位成功，重定位成功不等于绑定完成。没有真实进度就显示阶段文字，不造百分比，不以动画完成模拟成功。忽略过期定位回调。

至少为当前范围考虑权限拒绝、设备不支持、定位失败/丢失、绑定失败、横竖屏切换、App 失焦与恢复。给出真实可执行的下一步。位置失效时阻止依赖可靠位置的操作；暂停对局必须交给游戏系统决定，不假定能暂停联网的其他玩家。操作模块停用或失焦时取消持续输入。

实现时把主要按钮和 HUD 放在屏幕空间，把场地边界与位置标记放在世界空间。使用安全区域并正确转换屏幕/Canvas/面板坐标，旋转后更新；iOS 44pt、Android 48dp 的触摸目标参考不能直接写成 RectTransform 的 44/48 单位。中文字体需要实际资源和 fallback，不假设系统字体随 Unity 自动打包。深度与遮挡按设备和 SDK 检测，控制透明叠层与全屏特效，支持减少装饰动效。

交付页面布局、组件与状态、设计变量映射、真实事件绑定及资源清单；编码任务补充改动位置和实际测试结果。明确哪些是已确认、哪些是建议、哪些待确认；区分静态预览、Unity Editor、Android 真机与 iPhone 真机验证。没有运行的检查就写“未验证”，不能把 HTML 或模拟效果当成已完成 MR 游戏。

本次任务：先为“竖屏准备页、竖屏重定位页、横屏共享战斗 HUD”输出可供 Unity 开发接入的设计方案与组件拆分；操作方式继续保留可替换模块。若当前工程可访问，先检查工程现状，再按我本次明确要求的范围实现。
```
