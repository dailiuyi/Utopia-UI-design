# 手机 MR 决斗界面

把《攻壳机动队》的冷峻、机械与电脑界面气质转成能在手机摄像头画面上清楚阅读、触摸操作的 Unity UI。未指定作品版本时，以 1995 剧场版气质作为设计起点；具体色值和组件是本项目的设计提炼，不是官方 UI 规范。

交付范围由当前请求决定：设计请求输出设计，编码请求才修改工程，审查请求只报告问题。

## 产品与视觉约束

- Unity 6，具体 `6000.x`、UI 框架、渲染管线和包版本从目标项目读取。范围为 Android / iOS 手机，中文主界面，不扩展到头显。
- 原始决斗模板：竖屏准备与场景重定位、横屏战斗，相机对齐现实场景后呈现类似《拳皇》的虚拟决斗场；这不代表移动、连招、摇杆或攻击键规则已经确认。
- 复用于已有项目时，以用户当前要求与实际玩法、朝向、角色、操作为准，不因换肤新增血条、攻击键或强制横屏。当前不支持的平台不声称已支持。
- 操作未定时，保留共享 HUD 与可替换操作模块；直接操控、指令、观战只是候选。已有真实输入时按现有语义设计。
- 视觉目标：**冷黑与青灰底、低饱和电子绿主强调、青色定位与信息线、功能性 HUD、精密机械线稿**。琥珀色用于警告，红色用于危险；清晰黑体为主，数字与短编号等宽。
- 随包黑黄赛事海报仅辅助参考构图与机械细节，不再约束主题配色或强制中文衬线标题。
- 游戏名称、角色、联网、设备、定位与结算规则以目标项目为准；未知内容明确标注示例或待定。

## 按任务读取

1. 始终读取 [视觉规范](references/visual-language.md) 和 [设计变量](assets/design-tokens.json)。文字规范与变量足以离线使用；按需查看视觉规范中的官方作品参考与 `assets/reference-posters/` 辅助海报。没有实际查看图片时不声称完成视觉比对。
2. 制作页面、流程或组件时读取 [界面与状态](references/screens-and-states.md)。其中纵横屏决斗布局是模板，按目标工程适配，不默认扩展完整游戏。
3. 编码、技术接入方案设计或技术审查时读取 [Unity 接入与验收](references/unity-integration.md)。没有 Unity 工程时输出接入方案和待绑定事件，不虚构已完成的 Prefab、场景或编译结果。

## 工作方式

先读取工程事实，列出页面主动作、主信息与异常状态，再应用样式。准备页用冷色分层、结构编号和原创机械线稿建立科技气质；战斗页优先显示实际游戏内容、状态和操作。网格、坐标与扫描反馈对应真实对象或阶段，不以随机字符、假数据、满屏发光代替信息设计。

颜色、字级、间距、切角和动效取自设计变量；这些是项目建议起点，并非从作品精确测量的官方数值。已有主题变量时进行映射；玩家身份色与危险语义保留可识别性，不将所有状态染成同一种绿。

定位 UI 消费真实状态。设备追踪正常 ≠ 场景重定位成功 ≠ 场地绑定完成；动画结束不能触发成功。UI 不重写定位算法、战斗规则或联网逻辑。旋转改变布局，不重复创建场地、角色或对局。

## 完成时交付与核对

按任务规模交付页面层级、布局、所用变量、组件与状态、事件语义、资源清单。编码任务补充接入位置和实际验证结果；纯设计不生成无用工程骨架。

- 冷黑青灰、电子绿与青色细线形成统一科技气质；中文和实景清楚，琥珀/红色具有明确状态语义。
- 布局适配目标工程朝向与安全区；真实游戏状态、身份与退出可识别，未知操作仍保留边界。
- 权限拒绝、定位失败/丢失和旋转过渡有可执行的下一步；没有假进度、假成功。
- 明确用户确认、设计建议与待定部分。分别报告静态预览、Unity Editor、Android 真机、iPhone 真机；未执行即写“未验证”，不把 HTML、生成图或模拟运行当作真机验收。
