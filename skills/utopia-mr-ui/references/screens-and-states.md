# 界面、状态与可替换操作

以下为原始决斗模板的界面结构；复用于已有项目时按实际玩法、朝向和操作适配，不因主题变更强制新增战斗规则。按钮文案、回合数量、计时、角色名、生命数值仅为设计例子，实际规则以游戏逻辑为准。

## 建议页面

| 页面 | 朝向与主动作 | 布局重点 |
|---|---|---|
| 准备 | 竖屏；“寻找决斗场” | 上方简短标题与编号，中间决斗场说明/已有角色信息，底部主动作；角色选择仅在玩法需要时出现 |
| 重定位 | 竖屏；按提示对准已登记场景 | 相机全幅可见；顶部状态、中央轻量取景角、下方一句指导及取消/重试；匹配哪个场景由业务决定 |
| 场地确认与旋转 | 竖屏到横屏；“进入决斗场” | 只在实际定位与绑定成功后出现；提示横置手机，等待目标布局、安全区域和相机恢复稳定，不重复创建场地 |
| 战斗 | 横屏；行为由操作模块决定 | 顶部我方/对手生命条与回合状态，中部实景决斗场，底部两侧模块区域，易触达的暂停/退出 |
| 结算 | 优先保留横屏；返回准备后恢复竖屏 | 结果、与玩法相关的少量数据、再战/返回；是否支持原地再战由定位与游戏状态共同决定 |

准备页的宣传式标题不要迁移为战斗中永久占位的大字。尚无角色选择、段位、货币或多人系统时，不额外虚构这些页面。

### 竖屏定位

```text
安全区顶部：返回   寻找决斗场 / 当前定位阶段

        实景取景区（中央基本无遮挡）
          轻量角框、真实场地标记

深色短提示：对准已登记的场景，缓慢移动手机
底部：取消 / 必要时重试；成功后出现进入动作
```

### 横屏战斗

```text
安全区：我方 名称+生命条    回合/计时    对手 生命条+名称
        暂停入口保留足够触摸面积，不挤在计时小字中

                 相机实景 + 绑定的决斗场
                   双方角色与战斗反馈

可替换模块左区                              可替换模块右区
```

所有主要控件在屏幕坐标中保持稳定。世界空间标记绑定决斗场位置；既不随 UI 旋转而重新定位，也不让按钮贴在远处地面导致难以操作。若现实场地暂时不在视野中，提供真实方向指引/重新取景提示，不伪装为定位失败，也不把场地强行移到镜头前。

## 状态模型

以下是供应商无关的逻辑约定，不是 Unity 内置枚举或已存在的项目 API。接入时用 adapter/presenter 映射项目真实事件。

| 独立维度 | 建议逻辑状态 | 不能据此推导 |
|---|---|---|
| `CameraPermission` | unknown / requesting / granted / denied / restricted | 授权不代表已经拿到有效相机帧 |
| `DeviceCapability` | checking / supported / unsupported | 支持基础追踪不代表支持深度遮挡 |
| `Tracking` | initializing / tracking / limited / unavailable | tracking 不代表匹配到了已登记现实场景 |
| `Localization` | idle / searching / matched / failed / lost | matched 不代表场地资源、坐标绑定已准备好 |
| `ArenaBinding` | unbound / binding / ready / failed | ready 不代表对局规则或网络已允许开局 |
| `Orientation` | portrait / transitioning / landscape | 旋转完成不代表定位仍然有效 |
| `Match` | preparing / ready / running / suspended / finished | UI 动画完成不能决定战斗结算或暂停成功 |
| `ControlMode` | unspecified / direct / command / spectator | UI 示例不决定真实玩法或联网策略 |

如项目还有相机帧就绪、地图下载或联网准备状态，应补充实际依赖，不为了凑齐模型而创造无用状态。

进入战斗的条件建议为：相机可用、设备支持、业务要求的追踪有效、当前场景定位有效、场地绑定有效、目标朝向布局就绪、游戏逻辑允许开始。具体 SDK 若不使用 AR Foundation，应依照自己的有效性事件；不要强行依赖 `ARSessionState`。

场景匹配结果至少应能关联当前定位请求/会话、真实场景标识和位置变换；绑定结果也要对应当前场景。取消/重试、切换场景或后台恢复后，过期回调不能将旧状态显示成新成功。缺少进度或置信度数据时使用阶段文字与不定进度，不显示虚构的 `97%`。

### 异常与恢复

| 情况 | 页面行为 | 可执行动作 |
|---|---|---|
| 相机被拒绝/受限制 | 清楚说明需要相机，不持续“扫描中” | 返回、适用时前往系统设置；受系统限制时给出对应说明 |
| 基础能力不支持 | 说明本设备无法进入此 MR 模式 | 返回；仅当产品已有演示模式时提供该入口 |
| 定位等待较久或失败 | 根据 SDK 原因提示光照/纹理/网络；无原因时用通用提示 | 重新对准已登记场景、重试、取消；超时阈值由项目决定 |
| 已匹配但绑定失败 | “已找到场景，决斗场加载失败”等分阶段文案 | 重试资源/绑定；不要无条件重启相机或抹掉有效匹配 |
| 对战中定位/追踪丢失 | 优先恢复提示；禁用依赖可靠位置的操作，旧场地隐藏/淡化/保留由玩法决定 | 重新取景/定位、退出；不把漂移场地继续当可靠交互目标 |
| 手机偏离项目要求的朝向 | 按实际锁定方向给出旋转提示，保留本局信息 | 回到目标朝向恢复布局；本就使用竖屏的项目不要求横置，不销毁角色、锚点和比分 |
| App 失焦/后台/来电恢复 | 清空持续按压输入，重验权限、相机与定位有效性 | 满足真实恢复条件后再启用操作，不直接延续旧“成功”标签 |

异常遮罩优先级建议：权限/设备不可用 > 位置失效 > 朝向未就绪 > 普通战斗提示。同屏只展示最有行动价值的主提示，保留可用退出入口。恢复后重新计算可操作状态，不能简单关闭一个遮罩就恢复所有按钮。

暂停或恢复由游戏系统决定。UI 发出请求，并显示真实结果；单机可以由业务暂停模拟，联网对局可能只能禁止本地输入或执行服务器重连规则。联网方案尚未确认时，不承诺“定位丢失自动暂停所有玩家”。

## 操作模块

共享 HUD 按实际玩法显示生命值、回合等已有状态，以及定位和暂停/退出；没有生命或回合规则时不新增。将具体操作区隔离在独立 view/presenter 或 Prefab/模板中，接口命名适配现有项目，不要求固定类名。

| 候选模块 | 仅供评估的内容 | 必须向业务绑定的语义 |
|---|---|---|
| 未定 | 设计稿保留区域和说明；产品实现不展示开发占位文字 | 未有模块时仍可验收共享 HUD，不声称已经能完整对战 |
| 直接操控 | 按已有输入设计；双区方向/攻击仅为决斗示例，单摇杆项目保留单摇杆 | 按下、保持、抬起、取消；多点触控与同时输入；失焦清零 |
| 指令 | 可执行行动/技能及确认，可能有冷却/资源 | 指令可用条件、提交与拒绝、反馈；不要虚构卡牌规则 |
| 观战 | 信息展开、离开等必要控件 | 不产生角色攻击/移动输入；不默认增加自动镜头或回放功能 |

建议抽象能力：绑定对局视图数据、设置可交互状态、接收位置有效性变化、激活/停用模块、取消持续输入、发出业务动作请求。切换时解绑旧监听并清理旧输入，防止两个模块同时发动作。是否允许玩家在一局中切换由玩法确定，不是要求添加运行时模式选择器。

预览页可以提供候选模块切换用于讨论，但这个下拉框不属于游戏客户端需求。手指占用屏幕与双手持机时的镜头稳定性需要后续真机试玩，不能由“类似拳皇”推出已解决。
